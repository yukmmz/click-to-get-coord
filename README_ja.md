# click-to-get-coord

*[English](README.md) / 日本語*

ブラウザで **動画や画像** の上の点をクリックし、2つの基準点によるキャリブレーションで
**実世界座標** として取り出すツール。

アップロードもサーバーもインストールも不要。すべてブラウザの中で動く。

**→ [アプリを開く](https://yukmmz.github.io/click-to-get-coord/)**

## 機能

- **動画または画像** — 動画のフレームを送るか、複数の静止画を連番として読み込む
- **2点キャリブレーション** — 2点をクリックし、それぞれの実世界座標を入力するだけ
- **追加 / 削除モード** — フレームごとに点を記録し、いちばん近い点を消す
- **フレーム単位で正確な送り** — フレームレートは動画そのものから検出し
  （`requestVideoFrameCallback`）、訪れた各フレームのメディア時刻を記録する
- **フォルダへ保存** — 出力フォルダを選ぶと、すべての成果物をそこへ書き出す
- **あとで再開** — `session.json` を読み込めば続きから作業できる
- **日本語 / 英語の画面** — ブラウザの言語に合わせ、設定（⚙）で切り替えられる。
  訳すのは画面だけで、書き出すファイルはどちらの言語でも同じ
- **フィードバック（FB）** — 右上の FB ボタンから、ご意見や不具合の報告を開発者に送れる

## 使い方

1. **開く** / Open（Ctrl+O）— 動画ファイル、または1つ以上の画像ファイルを選ぶ（ドラッグ＆ドロップも可）
2. 自動でキャリブレーションモードになる。実世界座標がわかっている2点をクリックし、
   それぞれ `x,y` の形で入力する。2点は x と y の **両方** が異なるように選ぶ。
3. 自動で追加モードになる。クリックで点を記録する。`d` で削除モードに切り替わる。
4. **保存** / Save（Ctrl+S）— 出力フォルダを選ぶ。

### フレームの移動

連番全体にわたるシークバーがある。ドラッグするか、どこかをクリックすると、そのフレームへ飛ぶ。
`◀` / `▶`（と `←` `→` / `z` `x`）は **送り幅** だけ移動する。送り幅は 1 から始まり、ツールバーの
欄か `,` / `.` で変えられる（1, 2, 5, 10, 20, 50, 100, 200, 500）。`j` でフレーム番号へジャンプする。
バーのドラッグ中の要求はまとめられるので、速くドラッグしても途中のフレームを全部デコードせず、
指を離したフレームに落ち着く。

### 拡大縮小と移動

| 操作 | 動き |
|---|---|
| トラックパッドのピンチ、または `Ctrl/Cmd` + ホイール | カーソル位置を中心に拡大縮小 |
| 2本指スクロール | 移動 |
| ホイール / `Shift` + ホイール | 縦 / 横に移動（マウス） |
| `+` / `-` | 拡大 / 縮小 |
| `0` | フレーム全体が収まる表示に戻す |

3本指スクロールは macOS 自体が使ってしまい、ページには届かない。

### キーボードショートカット

| キー | 動き |
|---|---|
| `Ctrl/Cmd + O` | ファイルを開く |
| `Ctrl/Cmd + S` | 保存 |
| `c` / `a` / `d` | キャリブレーション / 追加 / 削除モード |
| `→` または `x` | 次のフレーム |
| `←` または `z` | 前のフレーム |
| `j` | フレーム番号へジャンプ |
| `,` / `.` | 送り幅を小さく / 大きく |
| `[` / `]` | 点の印を小さく / 大きく |
| `e` | 設定 — ⚙ と同じ（色、印の縁取り、なめらかな曲線、グラフの縦横比 など） |
| `?` または `h` | 使い方 — 右上の ? ボタンと同じ |
| `Esc` | 設定・QR コード・更新履歴・使い方・フィードバックの窓を閉じる |

### 途中でキャリブレーションをやり直す

いつでも `c` を押せばキャリブレーションをやり直せる。記録済みの点はそのまま残る。保存しているのは
画素座標なので、新しい基準点の組を確定すると、すべての実世界座標が計算し直される。新しい組が
確定するまでは今のキャリブレーションが有効なままなので、入力途中でやめても何も失わない。

### 印の見た目

印の縁取りの太さは印の大きさに合わせて変わる。4 px の点には細い線、20 px の点にはしっかりした
縁が付く。縁取りは設定で消せる。点の番号は既定で点と同じ色になる（図はたいてい明るい背景に
置くので、白にはしない）。番号だけ別の色にもできる。

### 作業の再開

保存すると、データの隣に `session.json` が書き出される。あとで続けるには、同じ動画や画像を
もう一度開き、**作業を再開**（Resume）を押して、その `session.json` を選ぶ。キャリブレーションと
記録したすべての点が戻る。動画や画像そのものはセッションファイルに保存されない。

### 設定・言語・共有

右上の ⚙ ボタン（または `e`）で設定が開く。変更はすべてその場で反映され、OK ボタンは無い。
✕、外側のクリック、`Esc` で閉じる。印やグラフの設定のほかに、言語（日本語 / English）、
アプリとソースの QR コード、更新履歴（アプリ名の横のバージョンを押しても開く）、他のアプリへの
リンクがある。隣の ⛶ は、ブラウザが対応していれば全画面表示を切り替える。? （または `?` / `h`
キー）は、すべてのショートカットを載せた使い方の窓を開く。閉じ方は更新履歴と同じ（閉じる、
外側のクリック、`Esc`）。

## ローカルで動かす

| 方法 | 確かめられること |
|---|---|
| `index.html` を直接開く（`file://`） | ファイルの読み込みと描画を含め、すべて。Chrome で確認済み。 |
| フォルダを http で配信し、`http://localhost:8000` を開く | 上と同じで、GitHub Pages での配信と同じ条件になる。VS Code の *Live Server* 拡張、`npx serve`、そのほか任意の静的サーバーを使う。 |
| `node tests/test_e2e_chrome.js` | ヘッドレス Chrome での自動 E2E 実行（画像 + 動画）。 |

`node tests/test_e2e_chrome.js` は使い捨ての静的サーバーを自分で立てる。`--file` を付けると、
サーバー無しで同じ検査をディスクから直接行う。

## 保存データ

このアプリがブラウザ（`localStorage`）に残すのは、ごくわずかなものだけである。⚙ で変えた設定
（`click-to-get-coord/settings`。フレームごとの PNG の切り替えは、ファイルを開くたびに決め直すので
残さない）、選んだ言語（`click-to-get-coord/lang`）、最後に見た更新履歴の版
（`click-to-get-coord/seen-version`）。設定のいちばん下の **保存データを消す** で、これらを
すべて消せる。動画・画像・点は保存しない。

外部へ送るものは無い。例外は FB（フィードバック）の窓で **送信** を押したときだけで、そこに書いた
内容を、アプリ名・バージョン・表示言語とともに開発者へ送る。動画・画像・点が送られることは無い。

## 出力

出力フォルダを選ぶと、次のファイルを書き出す。

| ファイル | 中身 |
|---|---|
| `coords.mat` | MATLAB Level 5 バイナリ。`coords_raw` / `coords_real` は `n_i × 2` の double を並べた 1×N の cell 配列で、元の Python ツールと同じ形。MATLAB と `scipy.io.loadmat` で読める |
| `coords.csv` | 全フレームの全点を1つのテキストファイルに。キャリブレーションは `#` のコメント行に入る |
| `plot_frame_XXXX.png` | そのフレームでクリックした点をキャリブレーション後の座標で描き、クリック順に線で結んだ図 |
| `overlay_frame_XXXX.png` | 元のフレームにクリックした点を重ねた、確認用の画像 |
| `session.json` | 状態をすべて含む。アプリで読み込み直せる |
| `README.md` | すべてのファイルとすべての列を説明した、単体で読める説明書 |

フレームごとの PNG は、既定で **画像ではオン、動画ではオフ**。注釈した動画クリップは数百枚の
ファイルと長い書き出しになりやすいためである。切り替えは設定（⚙）にあり、書き出される
`README.md` にどの PNG があるかが書かれる。数値はすべて `coords.mat` / `coords.csv` に入って
いるので、どちらを選んでも図はあとで描き直せる。

```python
from scipy.io import loadmat
d = loadmat('coords.mat')
pts = d['coords_real'][0][0]     # frame 0, shape (n_points, 2)
```

## キャリブレーション

2点から、回転を含まない軸ごとの1次変換を決める。

```
x_real = r0x + (x_img - p0x) * scale_x
y_real = r0y + (y_img - p0y) * scale_y
```

画像の Y は下向きに増えるので、実世界の Y 軸が上向きなら `scale_y` は負になる。これは元の
デスクトップ版ツールとまったく同じである。

## 対応ブラウザ

- **Chrome / Edge** — すべて使える。選んだフォルダへの全ファイルの書き出し
  （File System Access API）とフレームレートの検出も含む。
- **Safari / Firefox** — アプリは動くが、出力ファイルはフォルダへの書き出しではなく1つずつ
  ダウンロードされる。また Firefox はフレームレートを検出できない
  （30 fps として扱う。ツールバーで直せる）。

## 開発

ビルドの手順もパッケージマネージャーも **サーバー側のコードも無い**。アプリ全体は
`index.html` + `style.css` + いくつかの `.js` ファイル（と `qr.svg` / `src-qr.svg`、アイコン）で、
GitHub Pages が配信するのはまさにこれだけである。すべてブラウザの中で動く。

画面の文字は `app.js` の `STRINGS` 表（日本語と英語）にあり、`i18n.js` が当てはめる。`i18n.js` は
yukmmz.github.io のすべてのアプリで同じ内容のまま共有しているファイルである。

### テスト

Node だけで動き、パッケージは不要。

```
node tests/test_calib.js       # calibration maths
node tests/test_points.js      # per-frame point list
node tests/test_plot.js        # plot tick generation
node tests/test_exporters.js   # CSV / session / README / .mat encoding
node tests/test_wiring.js      # index.html <-> app.js consistency, STRINGS keys in both languages
node tests/test_e2e_chrome.js  # end-to-end in headless Chrome (needs Chrome installed)
```
